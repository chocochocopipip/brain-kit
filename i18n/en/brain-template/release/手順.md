## Common (all PRs)

1. Does the PR have the `<リリースラベル>` label and an instruction comment? If not, do not move.
2. With `gh pr view <N> --json headRefOid,files,mergeable,statusCheckRollup,labels`, check the difference between the head the review said OK to and the current head. If there is any difference other than merging main, stop and go to the partner.
3. If it is not on the current main, run `gh pr update-branch <N>`. If it conflicts, stop and go to <開発担当名>.
4. All named checks are SUCCESS (a blank in the rollup means not finished. Right after a rerun the job disappears, so wait).
5. If there is a migration, apply it **before the merge** and confirm with SELECT (see each repository below).
6. `gh pr merge <N> --squash --match-head-commit <head>`. Take the main sha before and after, and confirm it advanced.
7. The production deployment is READY at that sha. If needed, read production with SELECT.
8. When releasing several in a row, **wait until the main run is green**, then update-branch → CI → merge for the next PR.
9. One block in `記録/YYYY-MM-DD.md` (take the time from `date`), and one line to the partner.

## When stopped

If you are stopped by the classifier or permissions, do not retry in another form (getting the same result by another route is the same thing). One line to the partner: "Stopped: <PR / operation>, <reason>".
