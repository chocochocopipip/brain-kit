# Retrospective (the partner sums it up once a day)

The four (partner, <開発担当名>, <レビュー担当名>, <リリース担当名>) record, one line each, any move that left the procedure,
and return it to the skill or procedure of the one it applies to. The same way as the review criteria. **This table is not for blame. It is for not letting the same thing happen again.**

- One line per entry. "What happened" is facts only (no guesses)
- "Returned to" is the file you fixed (`review/規準.md`, `release/手順.md`, `dev/00_核.md`, a skill, etc.). If you decided not to return it, write "Not returned: reason"
- "Happened again": when the same type happens again, add the date. If it happens twice, change how you return it
- At month end, read the table from the top and pick up anyone whose type keeps recurring, and rows where "Returned to" is empty

| Date | Who | What happened | Type | Returned to | Happened again |
