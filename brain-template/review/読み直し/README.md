# 読み直し（月 1 回、答えを伏せて）

欠陥が分かっている過去の PR を、<レビュー担当名>に**答えを知らせずに**もう一度読ませ、今の規準で捕まえられるかを見る。
規準が育っているかの回帰の検査。成績は相棒が `評価/` に付ける。

## 流れ

1. **相棒が選ぶ**（月初め、3〜5 本）：評価の「見逃し」「本番で出た欠陥」の PR、`規準.md` の「過去の PR」。
   欠陥の無い PR も 1 本混ぜる（誤指摘を見るため）。今月と先月の `評価/` に出た PR は避ける（<レビュー担当名>が起動時に読むため）
2. **答えは相棒の領域に書く**：`<相棒名>/21_読み直しの答え.md`（どこに何の欠陥があったか）。
   <レビュー担当名>の worktree には相棒の領域が出ない。<レビュー担当名>はそこを読まない
3. **渡すのは `repo#PR` と読む head（欠陥が入っていた時点の sha）だけ。**欠陥の有無も型も言わない
4. **<レビュー担当名>が読む**：今の規準の版で、普段の手順どおり。PR にはコメントしない。
   後のコミット・コメント・issue・`評価/` のその PR の行は見ない（答えが見える）。
   結果は `読み直し/YYYY-MM.md`（[[読み直し/_テンプレート]] を写す）に書く
5. **相棒が突き合わせる**：答えと比べ、捕まえた／見逃し／誤指摘を `21_読み直しの答え.md` と `評価/YYYY-MM.md` の月次に書く。
   見逃した型は<レビュー担当名>に知らせ、規準に足すか決めてもらう（足すなら版を上げる。[[規準の版/README]]）
