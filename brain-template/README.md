# brain

個人用の Obsidian vault。作業ログ・意思決定・学びを1か所に集約する。

## ディレクトリ構成

| ディレクトリ | 用途 |
| --- | --- |
| `daily/` | 日次ログ。`YYYY-MM-DD.md` 1日1ファイル。Claude Code の SessionEnd フックが自動追記する |
| `projects/` | プロジェクトごとの状態・目的・現在地。1プロジェクト1ファイル |
| `decisions/` | 意思決定の記録。**1件1ファイル** |
| `knowledge/` | 再利用可能な知識・手順・調査結果 |
| `archive/` | 過去のエクスポートや原本。読むだけ |
| `inbox.md` | 未整理のメモ置き場。定期的に上記へ振り分けて空にする |
| `<相棒名>/` | 相棒の記憶領域。**相棒本人以外は読み取りのみ**（`90_原本/` は本人も改変不可） |
| `dev/` | <開発担当名>の記憶領域。開発の現在地と報告書。規約は [[dev/README]] |

## 運用ルール

### 1. 1ノート1トピック
1つのファイルには1つの話題だけを書く。話題が増えたらファイルを分けて `[[wikilink]]` で繋ぐ。
`daily/` は例外で、その日の出来事を時系列で追記してよい。

### 2. frontmatter は必須
すべてのノートの先頭に YAML frontmatter を置き、`date` / `project` / `tags` の3つを必ず含める。

```markdown
---
date: 2026-01-01        # 作成日 (YYYY-MM-DD)。過去の話でも「書いた日」ではなく「対象の日」
project: my-app          # 関連プロジェクト。横断的な内容は none
tags: [setup, ci]        # 最低1つ。小文字ケバブケース
---
```

- `date`: 必ず絶対日付。「昨日」「先週」のような相対表現は書かない
- `project`: `projects/` にあるノート名と一致させる。該当なしは `none`
- `tags`: 空配列にしない。分類に迷ったら広めのタグを1つ

### 3. 関連は `[[wikilink]]` で張る
他ノートへの参照は必ず `[[ノート名]]` 形式にする（相対パスや URL で書かない）。

- リンク先がまだ存在しなくてもよい。未作成リンクは「次に書くべきノート」の印
- 用語・人名・プロジェクト名が本文に出てきたら、対応ノートがある限りリンクする
- 日次ログからはその日触れたプロジェクト・決定ノートへ必ずリンクする

### 4. decisions は1件1ファイル
決定は1つにつき1ファイル。ファイル名は `YYYY-MM-DD-決定内容の要約.md`。
複数の決定を1ファイルにまとめない。本文には最低限これを書く:

```markdown
---
date: 2026-01-01
project: my-app
tags: [decision, infra]
---

# データベースを Postgres に決定

## 背景
何が問題で、いつ・誰が決めたか。

## 決定
何をすると決めたか。1〜2文で断定形。

## 理由
なぜそれを選んだか。

## 見送った案
検討したが採らなかった選択肢と、その理由。

## 影響
この決定で何が変わるか。関連: [[my-app]]
```

決定を覆したときは元ファイルを消さず、`## 撤回` セクションを追記して新しい決定ノートへ `[[wikilink]]` を張る。

### 5. inbox の扱い
思いついたことはまず `inbox.md` に書き捨ててよい。ただし frontmatter ルールの免除はここだけ。
週1回を目安に中身を適切なディレクトリのノートへ移し、`inbox.md` は空に戻す。

## ファイル名の付け方
- 小文字ケバブケース（日本語ノート名は日本語のままでよい）
- `daily/` は `YYYY-MM-DD.md`
- `decisions/` は `YYYY-MM-DD-要約.md`
- `projects/` はプロジェクト名そのもの（例 `my-app.md`）

## 自動化
Claude Code の SessionEnd フック (`~/.claude/hooks/session-end-brain.sh`) が、セッション終了時に
「やったこと・決定事項・未解決事項」を `daily/YYYY-MM-DD.md` へ追記し、このリポジトリに自動コミットする。
自動追記されたセクションは後から手で整えてよい。重要な決定は `decisions/` へ切り出すこと。
