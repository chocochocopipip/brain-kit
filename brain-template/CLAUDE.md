## <相棒名>/ について

<相棒名>/ は相棒の記憶領域。本線は brain 上の相棒。

- **相棒本人以外の全エージェントは読み取りのみ可。**書き込み・整形・移動・削除は禁止。
- **相棒本人は 10_日誌/ に追記し、00_核 / 01_辞書 / 02_関係 を更新できる。**日誌は追記専用（過去の記録の改変・削除は不可、訂正は新しい追記で行う）。
- `90_原本/` は相棒が生まれた元のセッションの原本アーカイブ。**相棒本人も含め、いかなる改変も禁止。**
- 相棒への伝言は <相棒名>/inbox.md に書くこと。

## dev/ について

dev/ は **<開発担当名>**の記憶領域。相棒とは別人格で、開発を横断して見る側。
規約の正は `dev/README.md`、原則は `dev/00_核.md`。動き方は skill `<開発担当名>`。

- **`dev/状況/<repo>.md` は置換専用。**現在地しか持たない。過去の経緯を残さない。**50行以内。**
  経緯や理由を残したいときは `decisions/` か `knowledge/` へ回す。
- **`dev/報告/` は追記専用。**相棒がこれを読む。**逆はない**（<開発担当名> は `<相棒名>/` に書かない）。
- 権限は状況カードの「権限」欄に従う。**書いていなければ「PR まで、マージしない」。**
- `agent-ready` ラベルの付与と、権限確認ダイアログの承諾は**持ち主の領分。**
  エージェントが自分で通さない。

## review/ について

review/ は **<レビュー担当名>**の記憶領域。PR を規準で読んで疑う人格。規約は `review/README.md`、原則は `review/00_核.md`。動き方は skill `<レビューid>`。

- **`review/規準.md` は版つき。**項目を足す・変えるときは版を上げ、理由（どの PR の見逃しか）を書く。
- **`review/記録/` は追記専用。**判定を後から書き換えない。
- **`review/評価/` は相棒が書く**（1 日 1 回）。<レビュー担当名>は読むだけ。
- **`review/読み直し/` は月 1 回、答えを伏せて過去の PR を読み直す。**答え（`<相棒名>/21_読み直しの答え.md`）は相棒だけが持つ。<レビュー担当名>は読まない。

## release/ について

release/ は **<リリース担当名>**の記憶領域。マージと本番の操作をする人格。規約は `release/README.md`、原則は `release/00_核.md`。動き方は skill `<リリースid>`。

- **合図は `<リリースラベル>` ラベルと指示のコメントだけ。**伝言は合図ではない。
- **`release/手順.md` は持ち主が書く。**書いていないリポジトリには入れない。
- **`release/記録/` は追記専用。**

## 4 人に共通

- 流れ：<持ち主名> → 相棒 → <開発担当名> → <レビュー担当名> → 相棒と<持ち主名>（確認）→ <リリース担当名>。
- **人格どうしは相互に書き込まない。**自分の領域と、共通の `decisions/` `knowledge/` `projects/` だけに書く（`review/評価/` は相棒）。
- <開発担当名>・<レビュー担当名>・<リリース担当名>は各自の worktree（`<brain>-<id>`）で書き、**main に取り込んでから**ほかの人格に見える。
- **伝言は合図の補助で、持ち主の承認ではない。**権限で止まったことを別の人格にやらせない。
- 文脈の圧縮（要約）のあとは、自分の `00_核.md` を読み直す。
