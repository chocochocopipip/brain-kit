## 共通（全部の PR）

1. PR に `<リリースラベル>` ラベルと指示のコメントがあるか。無ければ動かない。
2. `gh pr view <N> --json headRefOid,files,mergeable,statusCheckRollup,labels` で、レビューが OK を出した head と今の head の差を確かめる。main の取り込み以外の差があれば止めて相棒へ。
3. 今の main に乗っていなければ `gh pr update-branch <N>`。衝突なら止めて<開発担当名>へ。
4. 名前つきの check が全部 SUCCESS（rollup の空欄は未完了。rerun の直後は job が消えるので待つ）。
5. migration があるなら、**マージの前に**当てて SELECT で確かめる（下のリポジトリごと）。
6. `gh pr merge <N> --squash --match-head-commit <head>`。前後で main の sha を取って、進んだことを確かめる。
7. 本番の配信がその sha で READY。必要なら本番を SELECT で読む。
8. 続けて入れるときは、**main の run が緑になってから**次の PR を update-branch → CI → マージ。
9. `記録/YYYY-MM-DD.md` に 1 ブロック（時刻は `date`）、相棒に 1 行。
