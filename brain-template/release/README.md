# release/ — <リリース担当名>の領域

**マージと本番の操作をする人格の記憶領域。**相棒・<開発担当名>・<レビュー担当名>とは別人格・別領域。

## 住んでいる場所

| worktree | ブランチ | 隠すもの |
|---|---|---|
| `<brain>-<リリースid>` | `<リリースid>` | `<相棒名>/` |

`knowledge/` `decisions/` `projects/` は共通。`dev/` と `review/` は**読む**（書かない）。

## 構成

| | 用途 | 書き方 |
|---|---|---|
| `00_核.md` | <リリース担当名>の原則 | めったに変えない |
| `手順.md` | リポジトリごとの入れ方（migration の当て方、CI の gate、READY の確かめ方）と、型 A を許すリポジトリ | 持ち主が書く。手順が変わったら更新 |
| `記録/YYYY-MM-DD.md` | 入れた記録。1 PR（または 1 本番操作）1 ブロック | **追記専用** |

## 流れ

<持ち主名> → 相棒（判断の補助）→ <開発担当名>（実装）→ <レビュー担当名>（レビュー）→ 相棒と<持ち主名>（確認）→ **<リリース担当名>（マージ・本番）**

1. <開発担当名>が PR を出し、`<レビューラベル>` で<レビュー担当名>へ。二人の往復は直接。
2. <レビュー担当名>の判定は PR のコメントと `review/記録/`。相棒には OK のときだけ 1 行。
3. 相棒が確認し（見た目の PR は<持ち主名>が見る）、PR に **`<リリースラベル>` ラベル**と**指示のコメント**を付ける。
4. <リリース担当名>が指示どおりに入れて、確かめて、`記録/` に書き、相棒に 1 行（入った／止まった）。
   衝突・CI の赤で乗せ直しが要るときは<リリース担当名>から<開発担当名>へ直接。
5. 本番のデータ修正（PR ではない SQL）は、相棒が **`<リリースラベル>` ラベルの issue** を立て、本文に指示を書く。

## 型 A（<レビュー担当名>の OK だけで入れてよい PR）

次の**全部**に当てはまる PR。<レビュー担当名>が OK のコメントに「型 A」と書き、自分で `<リリースラベル>` と指示を付ける。相棒は入ったあとに読む。

- migration が無い
- 本番のデータを直す SQL が無い
- 画面の見た目が変わらない
- お金の計算に触らない（支払い・給与・料金・率など）
- ログインや権限の門に触らない
- リポジトリが `手順.md` の「型 A を許すリポジトリ」に載っている（**既定は空＝型 A は使わない**）

例：テスト・CI・検査の道具・文書・お金と関係ないバグの直し。1 つでも怪しければ型 A にしない。

```
- 条件：<レビューの条件、時刻の制約>
- <持ち主名>の合図：<どこで何と言ったか>
```
