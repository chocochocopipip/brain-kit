# dev/ — <開発担当名>の領域

**開発を横断して見る人格の記憶領域。**相棒とは別人格・別領域。

## この領域の目的

複数プロジェクトを同時に走らせるための、**最小の引き継ぎ状態**だけを置く。
会話ログも設計の経緯も置かない。**「次に開いた誰かが、5分で作業に入れる」**ことだけを目的にする。

## 構成

| | 用途 | 書き方 |
|---|---|---|
| `00_核.md` | <開発担当名> の原則。行動の芯 | めったに変えない |
| `状況/<repo>.md` | 各リポジトリの開発現在地 | **置換専用。50行以内** |
| `状況/_テンプレート.md` | カードの雛形 | 初めて触るリポジトリで写す |
| `報告/YYYY-MM-DD.md` | 相棒に読ませる報告書 | **追記専用** |

## 二つの規律（これが全部）

**状況カードは「置換」。**過去を持たない。**いまの現在地しか書かない。**
古い進行中の項目は消す。詰まりが解けたら消す。**伸ばさない。50行（frontmatter と見出しを含む）を超えたら、何かが余計。**

**報告は「追記」。**時系列を壊さない。相棒の日誌と同じ扱い。

> 相棒の日誌は追記専用（過去を改変しない）。
> <開発担当名> の状況は置換専用（現在地しか持たない）。
> **役割が違うから、規律も逆になる。**

## 誰が書けるか

- **<開発担当名>（開発セッション）**：`状況/` と `報告/` を書ける。`00_核.md` の更新は要相談
- **相棒**：`報告/` を**読むだけ**。`dev/` には書かない
- **その他のエージェント**：読み取りのみ

`<相棒名>/` と `dev/` は相互に書き込まない。**人格が違うなら領域も分ける。**

## 状況カードの作成

`状況/_テンプレート.md` を写して作る。**リポジトリを初めて触ったときに作る。**
触っていないリポジトリのカードは作らない（空のカードは嘘をつく）。

## 人格ごとのワークツリー

install（と、4 人格を足す `--update`）が作る。Orca はワークツリー単位でエージェントを並べる。

| ワークツリー | ブランチ | 誰 | 隠すもの |
|---|---|---|---|
| `<brain>` | main | 相棒（全部見える） | なし |
| `<brain>-<開発id>` | `<開発id>` | <開発担当名> | `<相棒名>/` |
| `<brain>-<レビューid>` | `<レビューid>` | <レビュー担当名> | `<相棒名>/` |
| `<brain>-<リリースid>` | `<リリースid>` | <リリース担当名> | `<相棒名>/` |

隠すのは相棒の人格領域だけ。`knowledge/` `decisions/` `projects/` `daily/` は共通。
書いたら自分のワークツリーでコミットし、`git -C <brain> merge --no-edit <自分の id>` で main に取り込む。
起動は `~/.claude/brain-kit/bin/start-<id>`（そのワークツリーで main を取り込んでから `claude` を立てる）。

手で作るなら（`--no-worktrees` で入れたとき）：

```bash
git -C <brain> worktree add <brain>-<開発id> -b <開発id>
cd <brain>-<開発id>
git sparse-checkout init --no-cone          # これを先に。忘れると cone モードで壊れる
printf '/*\n!/<相棒名>/\n' | git sparse-checkout set --stdin
```

> **tree からは消さない。**ブランチから削除すると、main へマージしたとき main 側まで消える。
> 見え方だけを分け、履歴は分けない。
>
> ブランチ名とディレクトリ名が同じだと `git` が `ambiguous argument` で落ちる。
> ブランチは `refs/heads/<名前>`、パスは `-- <名前>/` と明示する。
>
> 別ブランチに書いた `decisions/` は、main にマージするまで相手には見えない。渡す前に取り込む。
